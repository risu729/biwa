# Research notes

A research note records what was observed at a stated time, with primary sources:
a library or tool evaluation, a reproduction of an upstream bug, or a feasibility
check against UNSW CSE servers.

- Name the file `YYYY-MM-DD-topic.md` and start it with the date and the `main`
  commit it was checked against.
- Link primary sources (upstream docs, issues, source code at a fixed commit).
- Separate what was verified from what was inferred.
- Never present an old note as current; append new evidence or write a new note
  that supersedes it.
- A thread that researches something lands its note in its own docs PR, together
  with the [plan](../plan.md) lines it changes.
- Use synthetic examples. Never commit credentials, real zIDs, hostnames of private
  machines or other personal data.
